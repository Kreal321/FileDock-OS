# Phase 11 VM findings — code fixes, 2026-10-18

The five findings in [the PVE smoke report](./phase11-pve-smoke-2026-10-16.md) are addressed in
source. The fix request did not change the installed VM. A subsequent deployed-VM retest
verified these repairs and found a separate WebDAV visibility issue; see
[the installed retest report](./phase11-pve-retest-2026-10-18.md).

| Finding | Change |
| --- | --- |
| Partitioned OS disk reported as non-system | Disk discovery explicitly requests `lsblk --tree`, retaining root/swap descendants for classification and SMART association. |
| Hyphenated WebDAV folder fails to start | `systemd-run` dependency values preserve escaped unit-name backslashes; path properties use quoted words so spaces remain inside one entry. |
| WebDAV failure removes NFS while NFS remains Ready | Error cleanup removes only the failed protocol's entries/units. SMB and NFS apply independently; readiness reflects each backend's own apply result. |
| Shrink fails while removing NFS exports | Quiesce performs one aggregate NFS reload. The redundant per-rule unexport is removed. Sharing is serialized with storage maintenance so it cannot re-export a quiesced folder. |
| Azure picks schema-less Kopia | Non-S3 providers require a connection-schema owner. New connections prefer the available rclone schema owner used by OAuth. Edits retain the stored owner and block saving if it is unavailable rather than migrating credentials silently. OAuth controls appear only for the supported rclone owner. |

## Related recovery corrections

- NFS configuration application refreshes Debian's generated mount dependencies before a resize
  stops mounts. Changed configuration starts the enabled NFS service as needed, including after
  folder deletion, rather than leaving it stopped pending manual intervention.
- Applied configuration hashes are recorded only after successful backend application. A failed
  reload remains pending even if its desired file was already written or its last export was deleted.
- Pool-health changes enqueue reconciliation, so folders and dependent apps recover promptly.
- Journal step completion and operation state are committed atomically. A failed step records
  `failed` with its detail instead of remaining `acting` under a Failed operation.
